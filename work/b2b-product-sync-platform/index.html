The Problem

A global distributor exposed APIs to its partners under specific contracts. Each partner, in turn, had its own API with a different contract, authentication model, and protocol — some REST, some SOAP.

The platform needed per-client integrations to keep the website catalog in sync: product creation, stock levels, and pricing. The challenge was not a single integration, but ten distinct partner setups with different auth flows, field formats, and sync triggers — all while giving operations visibility into what succeeded, what failed, and why.

Integration Architecture

I designed and built the integration layer on Azure using a Logic Apps + Functions pattern:

Logic Apps — orchestrated each integration flow: scheduled runs (cron, twice daily), event-driven triggers (HTTP requests), step sequencing, and the overall structure partners could open and evaluate without reading application code.

Azure Functions (Node.js) — handled API calls between the distributor and each partner: authenticating against heterogeneous auth schemes, calling REST and SOAP endpoints, and transforming fields between incompatible contracts.

Product, stock, and pricing ran as separate integration flows. Pricing, for example, depended on the distributor's own price-publication cycle and could not share the same trigger or pipeline as catalog or inventory updates.

Most clients reused a shared Logic App template with per-partner variations; a few required fully dedicated flows where the contract diverged enough to justify a separate app.

API Design & Partner Onboarding

I adjusted and defined the distributor's integration-facing APIs, documenting contracts in Swagger so partner onboarding had a clear, versioned reference.

Each of the ten partner integrations required its own auth configuration, field mapping rules, and trigger setup — scheduled syncs, event-driven updates, or both depending on the partner's operational model.

Observability & Traceability

I added structured logging and audit storage in SQL Server: execution logs, product state snapshots, error records, and audit trails.

On failure, the system persisted an error summary plus the Logic App run ID so anyone could jump from the database record to the exact execution in Azure and diagnose the issue. This replaced silent failures that the previous setup did not catch.

Email alerts notified the team when a sync failed; retries were handled manually after review, keeping control over re-processing edge cases across heterogeneous partner APIs.

Tech Stack

Node.js · Azure Logic Apps · Azure Functions · SQL Server · REST · SOAP · Swagger · Cron & HTTP triggers

Impact

Ten production partner integrations covering product, stock, and pricing sync across a B2B catalog.

Full traceability of successful updates and failures, with execution IDs linked back to Logic App runs.

Eliminated silent sync errors and gave non-technical staff direct visibility into integration flows — increasing operational confidence without depending on developers for routine checks.
