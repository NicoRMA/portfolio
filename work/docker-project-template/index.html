The Problem

Every time the company started a new project from scratch, teams relied on manual setup without a shared baseline or service orchestration. Dependency versions, operating systems, local configs, and installed tools diverged between developers.

That inconsistency produced hard-to-diagnose environment errors and wasted days at the start of each project — sometimes several days per developer just to get the application running locally. Effort went into configuration instead of business features.

Template Design

I designed and built a reusable Docker-based template with a predefined project structure, standardized configuration, and fully reproducible environments via containers.

A Makefile drives local, development, and production workflows (`make local`, `make dev`, `make prod`) on top of layered Docker Compose files and per-environment env files. New projects inherit the same service layout, build patterns, and operational commands from day one.

Core services ship out of the box: React/Vite frontend, Node.js backend, PostgreSQL database, and an Apache reverse proxy with SSL and vhost configuration. Optional stacks extend the same base to Docker Swarm deployments and a monitoring layer (Prometheus, Promtail).

Multi-Environment Workflow

Each environment uses dedicated Compose overlays and Dockerfiles (local with hot-reload volumes, dev/prod with production-oriented images) so behavior stays predictable from a developer laptop to deployed infrastructure.

Proxy configuration, certificate generation, and vhost setup are scripted and documented — reducing one-off Apache/SSL work on every new project.

The template also supports pulling upstream updates from the base repository, so improvements to the standard can propagate to derivative projects without rebuilding everything manually.

Tech Stack

Docker · Docker Compose · Docker Swarm · Makefile · Node.js · React · Vite · PostgreSQL · Apache (reverse proxy, SSL, ModSecurity) · Prometheus · Promtail

Impact

Adopted as the internal standard for starting new developments and currently used across multiple company projects.

Unified technical criteria, consistent developer experience, and faster project kickoff — teams focus on business logic instead of fighting local setup.

Reduced developer onboarding time, improved team productivity, and increased environment reliability across the full development cycle.
